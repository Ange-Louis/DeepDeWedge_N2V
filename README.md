# DeepDeWedge_N2V

This repository is an adaptation of [DeepDeWedge](https://github.com/MLI-lab/DeepDeWedge), a method for simultaneous denoising and missing wedge reconstruction in cryogenic electron tomography, originally described in ["A Deep Learning Method for Simultaneous Denoising and Missing Wedge Reconstruction in Cryogenic Electron Tomography"](https://www.nature.com/articles/s41467-024-51438-y) (Wiedemann & Heckel, *Nature Communications*, 2024).

**DeepDeWedge_N2V replaces the original Noise2Noise training scheme with Noise2Void / Noise2Void2**, using the implementation provided by [CAREamics](https://github.com/CAREamics/careamics), a PyTorch toolbox for self-supervised denoising. The command line interface, the missing-wedge reconstruction logic, and the 3D U-Net architecture are otherwise unchanged from the original DeepDeWedge.

## Why Noise2Void / Noise2Void2 instead of Noise2Noise?

The original DeepDeWedge relies on **Noise2Noise** (Lehtinen et al., 2018): model fitting requires **two independently reconstructed tomograms** of the same specimen (e.g., from even and odd tilt series frames), sharing the same underlying signal but with independent noise realizations. This works well, but it is not always practical — some acquisition or reconstruction workflows only produce a single usable tomogram.

**Noise2Void** (Krull, Buchholz & Jug, *CVPR*, 2019) removes this requirement entirely. Instead of comparing two independent noisy observations, it uses a *blind-spot masking* scheme: during training, a small random subset of voxels in each sub-tomogram is masked and replaced with a value drawn from their local neighborhood, and the network is trained to predict the original (masked) value from context alone. Because the noise is assumed to be voxel-wise independent given the signal, this works using only a **single** noisy tomogram, no paired reconstruction needed.

**Noise2Void2** (Höck, Buchholz, Brachmann, Jug & Freytag, *ECCV Workshops*, 2022) refines this scheme to reduce checkerboard artifacts that can appear in vanilla Noise2Void reconstructions, primarily by replacing masked voxels with the **median** of their neighborhood instead of a randomly sampled neighbor. DeepDeWedge_N2V adopts this alternative sampling strategy (available via a configuration flag, see below); the additional network-architecture changes proposed in the N2V2 paper (BlurPool instead of MaxPool, a non-residual U-Net, no uppermost skip connection) are **not** part of this repository, which keeps the original DeepDeWedge 3D U-Net used for the missing-wedge reconstruction task.

**In practice, this means `prepare-data`, `fit-model` and `refine-tomogram` now all operate on a single tomogram per specimen**, instead of a pair of independent reconstructions.

## Installation

Clone this repository together with your local checkout of CAREamics (used here purely as a function library for the N2V/N2V2 blind-spot masking, not for its own training pipeline):
```
git clone <your-fork-url> DeepDeWedge_N2V
cd DeepDeWedge_N2V
# careamics/ should already contain a full checkout of https://github.com/CAREamics/careamics
# with your local modifications, laid out as careamics/src/careamics/...
```
This project uses [`uv`](https://docs.astral.sh/uv/) for environment management. From the repository root:
```
uv sync
```
This creates a `.venv` virtual environment, resolves and installs all dependencies (including `careamics`, referenced as a local editable dependency — see `pyproject.toml`), and installs the `ddw` command line interface. PyTorch is installed with CUDA 12.1 support by default; adjust the `pytorch-cu121` index in `pyproject.toml` if you need a different CUDA version.

Activate the environment and verify the installation:
```
source .venv/bin/activate
ddw --help
```

## Usage

The `ddw` command line interface provides the same three commands as the original DeepDeWedge, now all operating on a single tomogram per specimen:
- `ddw prepare-data`: Extracts cubic sub-tomograms from a single tomogram, used to generate model inputs and targets for model fitting.
- `ddw fit-model`: Fits a U-Net for denoising and missing wedge reconstruction using Noise2Void or Noise2Void2 training, on data generated by `prepare-data`.
- `ddw refine-tomogram`: Refines one or more tomograms using a fitted model. No blind-spot masking is applied at this stage — only the missing-wedge reconstruction learned during training.

Each command's arguments can be shown with `ddw <command> --help`. Arguments can be provided either directly on the command line, or via a single `YAML` configuration file shared across all three commands. All commands are also available as plain Python functions inside the `ddw` package.

### With a config file

```
ddw prepare-data --config config.yaml
ddw fit-model --config config.yaml
ddw refine-tomogram --config config.yaml
```

Example `config.yaml`:
```yaml
shared:
  project_dir: "./my_project"
  tomo_files:
    - "./my_data/tomo.rec"
  subtomo_size: 96
  mw_angle: 50
  num_workers: 10
  gpu: 0
  seed: 42

prepare_data:
  mask_files:
    - "./my_data/mask.mrc"
  min_nonzero_mask_fraction_in_subtomo: 0.3
  subtomo_extraction_strides: [64, 80, 80]
  val_fraction: 0.2

fit_model:
  unet_params_dict:
    chans: 64
    num_downsample_layers: 3
    drop_prob: 0.0
  adam_params_dict:
    lr: 0.0004
  n2v_manipulate_params:
    strategy: "median"           # "median" = Noise2Void2, "uniform" = Noise2Void
    roi_size: 11
    masked_pixel_percentage: 5.0
  num_epochs: 1000
  batch_size: 5
  update_subtomo_missing_wedges_every_n_epochs: 10
  check_val_every_n_epochs: 10
  save_n_models_with_lowest_val_loss: 5
  save_n_models_with_lowest_fitting_loss: 5
  save_model_every_n_epochs: 50
  logger: "csv"

refine_tomogram:
  model_checkpoint_file: "./my_project/logs/version_0/checkpoints/.../epoch=999.ckpt"
  subtomo_overlap: 32
  batch_size: 10
```

### Without a config file

Every argument can also be passed directly on the command line, for example:
```
ddw prepare-data \
  --tomo-files ./my_data/tomo.rec \
  --mask-files ./my_data/mask.mrc \
  --subtomo-size 96 \
  --project-dir ./my_project \
  --min-nonzero-mask-fraction-in-subtomo 0.3 \
  --val-fraction 0.2

ddw fit-model \
  --unet-params-dict "{'chans': 64, 'num_downsample_layers': 3, 'drop_prob': 0.0}" \
  --adam-params-dict "{'lr': 0.0004}" \
  --n2v-manipulate-params "{'strategy': 'median', 'roi_size': 11, 'masked_pixel_percentage': 5.0}" \
  --num-epochs 1000 \
  --batch-size 5 \
  --subtomo-size 96 \
  --mw-angle 50 \
  --gpu 0 \
  --num-workers 10 \
  --project-dir ./my_project \
  --seed 42

ddw refine-tomogram \
  --tomo-files ./my_data/tomo.rec \
  --model-checkpoint-file ./my_project/logs/version_0/checkpoints/.../epoch=999.ckpt \
  --subtomo-size 96 \
  --mw-angle 50 \
  --subtomo-overlap 32 \
  --batch-size 10 \
  --gpu 0
```

### Choosing between Noise2Void and Noise2Void2

This is controlled entirely by the `strategy` field of `n2v_manipulate_params` in `fit-model`:
- `"uniform"` → Noise2Void (default): masked voxels are replaced with a randomly sampled neighboring voxel.
- `"median"` → Noise2Void2: masked voxels are replaced with the median of their local neighborhood, which tends to reduce checkerboard artifacts.

Other relevant fields: `roi_size` (size of the neighborhood used for replacement, must be odd), `masked_pixel_percentage` (fraction of voxels manipulated per sub-tomogram), and `seed` (for reproducibility of the masking).
